# ربط هوية OpenID بحساب محلي

تسجل الحزمة مسار تعديل وسيلة المصادقة ومسار الدخول بكلمة مرور مرتبطة داخل
`enterprise/`، دون تغيير `mattermost/server/`. لا يسمح تعديل وسيلة المصادقة
إلا لمسؤول النظام ومع رخصة نشطة. يمكن ربط معرّف OpenID غير المملوك لحساب
آخر بحساب محلي. تحفظ كلمة مرور الحساب الهدف في جدول
`workspace_linked_credentials` كي يبقى دخوله المحلي ممكنًا بعد تحويل
وسيلة المصادقة إلى OpenID؛ يظل حقل كلمة المرور الأصلي فارغًا. تعالج صفحة
تعديل اسم OpenID الحسابات التي رُبطت قبل تصحيح هذا الحقل: تمسح النسخة
المكررة من سجل المستخدم فقط عندما تطابق اعتماد الدخول المحفوظ تمامًا.
عند ربط معرّف OpenID غير مستخدم عبر مسار الإدارة، يُحفظ اعتماد الدخول المحلي
ويتغير معرّف المصادقة ضمن معاملة واحدة. إذا فشل التغيير، تتراجع العمليتان
ويبقى الحساب المحلي وكلمة مروره بلا سجل اعتماد إضافي. يغطي الاختباران
`TestOpenIDAuthFailureDoesNotSaveLocalCredential` و
`TestOpenIDAuthAndLocalCredentialCommitTogether` حالتي التعارض والنجاح؛
نجح `go test ./account_linking -count=1` و`go vet ./account_linking`
في 1 أكتوبر 2026.
إذا ربط المسؤول معرّف OpenID غير مستخدم بالحساب المحلي عبر المسار القديم،
ثم أعاد وسيلة الدخول إلى البريد، تُستعاد كلمة المرور المحفوظة في المعاملة
نفسها التي تزيل هوية OpenID وصف الاعتماد المؤقت. لا يسري هذا المسار على
زوج حسابات مربوط؛ يجب استخدام `openid_unmerge` له. أثبت اختبار API
`TestLinkUnusedOpenIDIdentityKeepsLocalHistoryAndPassword` إمكان الدخول
المحلي بكلمة المرور الأصلية بعد العودة وحذف الاعتماد المؤقت. نجح
`go test . ./account_linking -count=1` و`go vet . ./account_linking`
في 1 أكتوبر 2026.
إذا كان المعرّف مملوكًا لحساب OpenID موجود، يرفض مسار تعديل المصادقة القديم
العملية بـ`409` ويبقي الحسابين وبياناتهما كما هي. يستخدم المسؤول في هذه
الحالة زر «ربط بحساب ابن ايدي» في صفحة المستخدم؛ ينفذ
`POST /users/{id}/openid_merge` بعد اختيار حساب OpenID غير مرتبط من القائمة.
الربط الجديد ينقل معرّف الدخول فقط إلى الحساب المحلي، فتفتح كلمة المرور
وOpenID معرّف المستخدم المحلي نفسه. لا ينقل رسائل أو ملفات أو عضويات
الحساب OpenID السابق. يبقى ذلك الحساب محفوظًا ومعطّل الدخول طوال الربط،
ثم تعود إليه هوية OpenID عند الفك. تحفظ كلمة مرور المحلي في
`workspace_linked_credentials` خلال الربط. يختبر هذا المسار
`TestFastOpenIDLinkKeepsBothAccountsDataAndCanUnlink`، بما في ذلك إعادة الربط.
أثناء وجود رابط فعّال، يرفض مسار الإدارة القديم
`PUT /users/{id}/auth` تغيير وسيلة دخول أي من الحسابين بـ`409`؛ يجب فك
الربط عبر `openid_unmerge` أولًا كي لا يتعطل سجل الرابط أو تُفقد هوية
OpenID. أثبت اختبار API ذلك للحساب المحلي والمصدر مع بقاء مالك الهوية،
ونجح `go test . ./account_linking -count=1` و`go vet . ./account_linking`
في 1 أكتوبر 2026.
يحفظ الربط السريع معرّف OpenID الأصلي في `workspace_openid_fast_links`،
ويرفض الفك بـ`409` إذا تغيّر المعرّف في الحساب المحلي بعد الربط؛ فلا يُعاد
معرّف مختلف إلى حساب المصدر. الروابط السريعة الأقدم من إضافة هذا الحقل
لا تملك لقطة للمعرّف، لذلك لا يمكن لهذا الفحص تأكيد معرّفها الأصلي.

الروابط المنشأة **قبل** تغيير المسار قد تكون دمجت بيانات الحسابين بالفعل.
تعرفها الخانة `fast_link: false` في حالة الربط، وتبقى خاضعة لقواعد الفك
القديمة المبينة أدناه؛ لا يزيل المسار الجديد نقل البيانات التاريخي تلقائيًا.

المسار التاريخي `mergeAccountsDB` ما زال موجودًا لاستيعاب اختبارات الدمج
والفك القديمة فقط، ولا تستخدمه واجهة الربط الجديد.
عند دمج محادثتين مباشرتين، تُنقل تفضيلات فتح المحادثة التي تستخدم معرّف
القناة مفتاحًا إلى المحادثة الباقية. تبقى قيمة المحادثة المحلية عند التعارض،
وتُحفظ القيم الأصلية لاستعادتها عند فك الربط. لا تمنع سجلات الفك السابقة
إعادة الربط.
الدمج مشروط: إذا وجد مرجع بيانات لا تعرف الحزمة نقله أو تعارض محادثات أو
صلاحيات، يعيد `409` وتتراجع المعاملة كاملة دون تعديل الحسابين. ينقل الحالات
المدعومة من رسائل وملفات وعضويات وتفضيلات ومحادثات مباشرة وجماعية غير
متعارضة، ويحفظ كلمة مرور الحساب المحلي ويجعل دخول OpenID يشير إلى معرّفه.
إذا كان حساب OpenID لا يملك اعتمادًا محليًا مرتبطًا، فلا يستطيع صاحبه إنشاء
كلمة مرور محلية لنفسه بمجرد وجود جلسة SSO. يُرفض الطلب بـ`403` ولا ينشأ
صف اعتماد؛ يستطيع المسؤول المخوّل إدارة كلمة المرور عبر المسار المخصص.

يختبر `TestUpdateOpenIDAuthRejectsPartialConsolidation` رفض النقل الجزئي
وبقاء الحسابين ومنشور المصدر، ويختبر
`TestUpdateOpenIDAuthRequiresAdminAndLicense` رفض المستخدم العادي ورفض
المسؤول بلا رخصة مع بقاء وسيلة مصادقة الهدف كما كانت.
يختبر `TestLinkUnusedOpenIDIdentityKeepsLocalHistoryAndPassword` حالة معرّف
OpenID الذي لم ينشئ حسابًا منفصلًا: تبقى رسائل الحساب المحلي، وتعمل كلمة
المرور، ويعيد البحث بهوية OpenID معرّف الحساب المحلي نفسه.
يغطي `TestUnlinkedOpenIDUserCannotCreateLocalPassword` منع إضافة وسيلة دخول
محلية لحساب SSO غير مرتبط بواسطة صاحبه، ويسمح بإجرائها للمسؤول المخوّل؛
أُعيد أيضًا اختبار تغيير كلمة مرور الحساب المرتبط.

يوفر `GET /users/openid_link_candidates` قائمة حسابات OpenID للمسؤول،
ويوفر `GET /users/{id}/openid_merge_status` حالة الربط المحفوظة واسم حساب
OpenID ونوع الربط. ويوفر
`GET /users/{id}/openid_merge_preview?source_user_id=...` معاينة
جزئية للمراجع وتصادمات المفاتيح. تبقى `complete: false` حتى يكتمل جرد
الرسائل والعضويات وسائر البيانات التابعة، بما فيها بيانات الإضافات.
تفاصيل شروط الرفض وحدود التغطية في `MERGE_CONTRACT_AR.md`.

تسمح صفحة المستخدم للمسؤول بتعديل الاسم الأول واسم العائلة لحساب OpenID
عبر `PUT /users/{id}/openid_name`. يقتصر المسار على مسؤول النظام مع رخصة
نشطة وحساب OpenID فعّال؛ لا يغيّر اسم المستخدم أو البريد أو معرّف المصادقة.
يحتفظ مزود OpenID في هذا المشروع بالاسم المخزن عند الدخول التالي.

يوفر `POST /users/{id}/openid_unmerge` فك الربط من صفحة المستخدم، مع تأكيد
منفصل. للربط الجديد يعيد هوية OpenID إلى حساب المصدر وكلمة مرور الحساب
المحلي إلى سجله داخل معاملة واحدة، دون تعديل الرسائل والملفات والعضويات.
تُلغى جلسات الحسابين بعد النجاح.
طلبا الربط والفك يقبلان كائن JSON واحدًا بحقول معلومة وبحد 4 KiB؛ يردان
`400` للحقل أو القيمة الإضافية و`413` للجسم الكبير، قبل تغيير أي هوية.
أثبت اختبار API بقاء مالك OpenID الأصلي بعد رفض الربط، وبقاء الرابط بعد رفض
الفك. نجح اختبار الجذر الموجّه، و`go test ./account_linking -count=1`،
و`go vet . ./account_linking` في 1 أكتوبر 2026.
ينطبق التحقق نفسه على مسار الإدارة `PUT /users/{id}/auth`: أثبت اختبار API
رفض الحقل أو JSON الإضافي والجسم الكبير مع بقاء وسيلة دخول الحساب المحلي
وعدم حفظ نسخة كلمة المرور قبل الطلب الصحيح. نجح اختبار الجذر الموجّه
واختبار الحزمة و`go vet`.
يُرفض JSON `null` أيضًا في قارئ الطلبات المشترك؛ كان يمكن أن يتحول إلى طلب
فك فارغ. أثبت اختبار API بقاء ربط OpenID بعد رفضه، ونجح اختبار الجذر
الموجّه وحزمة الربط و`go vet` في 1 أكتوبر 2026.

للربط التاريخي ذي نقل البيانات، يستعيد محادثات DM والإعدادات والعضويات
المدعومة من الأرشيف داخل معاملة واحدة. تبقى الرسائل والملفات التي أُنشئت بعد الربط
في الحساب المحلي عند إرسال `preserve_new_on_local: true`، بغض النظر عن
طريقة الدخول التي استُخدمت لإنشائها. تُلغى جلسات الحسابين بعد النجاح.
إذا تغيّرت محادثة مباشرة مدمجة، أو ظهر نشاط جديد في الحساب المصدر، أو نقصت
لقطة الاستعادة، يرد `409` ولا يغيّر الحسابين. يحتفظ بتاريخ عملية الفك في جدول مستقل.
تستعيد الاستعادة التاريخية أيضًا ملكية المنشورات والملفات وعضوية الفريق
والقنوات وتصنيفات الشريط والقنوات المباشرة التي سُجلت في الأرشيف. جُرّبت
على نسخة معزولة من `sofa_backup` التي فيها الربط السابق لـ`don`، ثم جُرّب
ربط الحسابين مجددًا بالمسار السريع. تبقى أشكال بيانات إضافية غير مدعومة
سببًا لرفض الفك حفاظًا على الحسابين.
