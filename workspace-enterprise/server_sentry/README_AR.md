# مراقبة أخطاء خادم Go عبر Sentry

يستخدم الخادم نقطة الربط الموجودة أصلًا في Mattermost: عند بدء التشغيل
يقرأ `app.SentryDSN` ويهيئ `sentry-go` ومراقبة أخطاء HTTP. تضبط هذه الحزمة
العنوان من `WORKSPACE_SERVER_SENTRY_DSN` داخل `workspace-enterprise` قبل تلك
الخطوة. لا تُعدّل ملفات `mattermost/server/` ولا تحفظ DSN الخادم في صفحة
إعدادات المتصفح.

لتفعيل الإرسال، اضبط على كل عقدة:

```text
WORKSPACE_SERVER_SENTRY_DSN=https://public-key@your-sentry-host/project-id
MM_LOGSETTINGS_ENABLEDIAGNOSTICS=true
MM_LOGSETTINGS_ENABLESENTRY=true
MM_SERVICEENVIRONMENT=production
```

يحتاج التشغيل رخصة Enterprise محملة عند بدء الخادم. في بيئة `dev` يعطل
مسار Mattermost الأصلي إرسال Sentry حتى مع ضبط العنوان. إذا غابت الرخصة أو
كان العنوان فارغًا أو غير صالح، يبقى عنوان Sentry فارغًا ولا تُرسل أحداث
خادم إلى عنوان Mattermost الافتراضي. العنوان يحتاج HTTPS ومفتاح مشروع،
ولا يقبل كلمة مرور. يُتجاهل المتغير العام `SENTRY_DSN` لأن SDK قد يستخدمه
بديلًا عند فراغ العنوان، بما يتجاوز شرط الرخصة. بعد تغيير العنوان أو إعدادات
التشغيل أعد تشغيل كل عقدة. يفحص معالج الأحداث وجود الرخصة عند التقاط كل
حدث؛ إذا أُزيلت أثناء التشغيل تُسقط الأحداث الجديدة. الأحداث التي دخلت
طابور الإرسال قبل إزالة الرخصة قد تكون قد أُرسلت بالفعل.
يتولى مسار Mattermost الموجود مسبقًا إرسال أخطاء HTTP؛ هذه الإضافة لا تدعي
التقاط كل رسائل السجل ولا جميع الأخطاء التي يعالجها التطبيق دون panic.
يستدعي بناء الخادم مصنع Enterprise داخل `NewChannels` قبل تهيئة
`sentry-go` في `NewServer`، لذلك يصل العنوان المصرّح به إلى مسار التهيئة.
نجح اختبار محلي بمستقبل HTTPS مؤقت: وصل حدث SDK تجريبي إلى عنوان Enterprise،
ولم يُرسل حدث بعد تعطيل الرخصة حتى مع وجود `SENTRY_DSN` عام. اختُبر كذلك
إسقاط حدث بعد إزالة الرخصة أثناء عمل العميل واستئناف الإرسال عند عودتها.
نجح أيضًا
اختبار طلب HTTP إلى خادم محلي يسبب `panic`: تحقق الاختبار من تنفيذ المعالج
ومن وجود نص الخطأ في الحدث الذي وصل إلى مستقبل HTTPS. يستخدم الاختبار رخصة
تجريبية ومسار تهيئة يحاكي ترتيب بدء الخادم؛ لا يثبت التشغيل على خادم منشور.

صفحة `/admin_console/environment/browser_sentry` تخص SDK المتصفح وإعادة
الجلسات فقط. تبقى سياستا المتصفح وخادم Go مستقلتين، ويمكن توجيههما إلى
مشروعي Sentry مختلفين. يلزم اختبار إرسال حدث فعلي إلى مشروع Sentry خارجي
قبل اعتماد المراقبة في الإنتاج.
