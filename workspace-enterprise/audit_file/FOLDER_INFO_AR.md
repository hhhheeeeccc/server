# وظيفة مجلد `audit_file`

قراءة سجلات التدقيق الملفية وحالتها وصفحاتها، مع إثراء سياق السجلات دون تعديل السجل الأصلي.

ملفات بارزة: `api_integration_test.go`، `enrichment.go`، `enrichment_test.go`، `pagination.go`، `pagination_test.go`، `service.go`، `service_test.go`.

هذا الوصف يحدد دور المجلد؛ حالة اكتمال الميزة وحدود اختبارها موثقة في [خطة النواقص](../docs/REMAINING_FEATURES_AR.md).

في 1 أكتوبر صار مسار قراءة السجلات القديم يعيد مصفوفة فارغة عندما يكون
التسجيل مفعّلًا لكن ملف السجل لم يُنشأ بعد، كما يفعل مسار الصفحات. لا تُخفى
أخطاء القراءة الأخرى. نجح اختبار الملف المفقود والفارغ و
`go test ./audit_file -count=1` و`go vet ./audit_file`، ثم اختبار API بعلامة
`integration`. تبقى تجربة تدوير ملف سجل فعلي أثناء
القراءة على عقدتين ومخزن سجلات مشترك.

في 1 أكتوبر، صار مؤشر الصفحات يضم هوية الملف المفتوح من الجهاز ورقم inode
عندما يوفرهما نظام التشغيل. يرفض ذلك متابعة مؤشر ملف استُبدل بعد التدوير،
حتى إذا تطابق الحجم وأول وآخر 64 KiB؛ وتبقى الإضافة إلى الملف نفسه مقبولة.
نجح اختبار الاستبدال بهذه الحالة، واختبارات الحزمة و`go vet` وAPI بعلامة
`integration`. على الأنظمة التي لا توفر هاتين القيمتين يبقى كشف التغيير
معتمدًا على بصمة محتوى البداية والنهاية؛ ويلزم اختبار تدوير السجل على
خادم منشور وعقدتين.
في 1 أكتوبر، صار مسار حالة السجل يميّز بين ملف لم يُنشأ بعد (مفعّل بلا
سجلات) ومسار لا يمكن قراءته أو يشير إلى دليل (خطأ قراءة)، بدل إظهار
الحالتين الأخيرتين كأن السجل فارغ. نجحت اختبارات الملف واختبار API بعلامة
`integration` و`go vet ./audit_file`.
