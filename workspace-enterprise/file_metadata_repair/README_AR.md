# إصلاح قراءة وصف المرفقات المستعادة

## السبب

سجل فحص 209 بتاريخ 15 أكتوبر 2026 أظهر:

```text
sql: Scan error on column index 8, name "thumbnailpath":
converting NULL to string is unsupported
```

قارئ `FileInfo` في الخادم الجاري يقرأ الحقول الأربعة التالية في متغيرات
`string`، ولا يعالج NULL فيها. رُصدت 20 قيمة NULL في `thumbnailpath`،
و20 في `previewpath`، وقيمتان في كل من `extension` و`mimetype`.
هذه أعداد قيم لكل عمود وقد تخص الصفوف نفسها؛ ليست عدد ملفات مفقودة.

## الملفات

جميع المسارات تحت `/home/marwan/المستندات/workspace-enterprise/`:

| الملف | التغيير |
| --- | --- |
| `file_metadata_repair/repair.go` | عملية مستقلة لفحص NULL وتطبيعها إلى نص فارغ مع أرشيف داخل معاملة واحدة. |
| `file_metadata_repair/repair_test.go` | اختبارات PostgreSQL حقيقية: إعادة إنتاج الخطأ وإصلاحه، حفظ باقي البيانات، التكرار، التراجع، رفض قاعدة خاطئة ومعرّفات غير سليمة وفشل قيود التحديث. |
| `cmd/workspace-file-metadata/main.go` | أداة تقرأ ملف إعدادات JSON المحدد؛ الفحص للقراءة فقط افتراضيًا، والتطبيق يحتاج `-apply`. |

لم يُعدّل مصدر الخادم الأساسي. بدءًا من إصلاح أداء 209 بتاريخ 18 أكتوبر 2026،
يستدعي `main.go` عملية الإصلاح عند بدء Enterprise قبل تقديم واجهات API، مع
حفظ القيم الأصلية في أرشيف عند وجود قيم NULL. الأداة المستقلة تبقى للقراءة
فقط افتراضيًا. لا تتغير بايتات المرفقات أو التراخيص أو سجل الترحيلات.

**تكامل الترحيلات:** يستدعي `cmd/workspace-db-migrate` العملية نفسها بعد نجاح
ترحيلات الكور وفحص البنية. تشغيل الأداة المستقلة أدناه يبقى للقراءة فقط
ما لم تحدد `-apply`. تفاصيل ربط الترحيل بالخدمة في
[`../deployment/database/README_AR.md`](../deployment/database/README_AR.md).

## السلوك

- يطابق اسم القاعدة الفعلي مع `-database`، ويرفض الاختلاف.
- يحل جدول `fileinfo` وفق `search_path` ويستخدم اسم المخطط صراحة في الاستعلامات التالية.
- عند التطبيق، ينتظر قفل الكتابة حتى خمس ثوانٍ؛ القراءة العادية تستمر. حد الاستعلام 30 ثانية والعملية 90 ثانية.
- يرفض معرّفات NULL أو مكررة قبل التعديل.
- يحفظ المعرف والحقول الأربعة للصفوف المتأثرة في جدول
  `workspace_fileinfo_nulls_<UTC timestamp>_<random>` داخل مخطط الجدول الأصلي.
- يبدل NULL فقط إلى `''` دون تعديل مسارات الملفات الأصلية أو الربط بالرسائل أو الأسماء أو الأحجام أو الأوقات أو بايتات المرفقات.
- أي خطأ يلغي التحديث وجدول الأرشيف معًا؛ التكرار بعد النجاح لا يغيّر شيئًا.
- يعيد تقرير JSON باسم الأرشيف واستعلام تراجع. استعلام التراجع يتجاوز الصفوف التي تغير وصفها بعد الإصلاح حتى لا يمسح وصفًا أحدث. تجب مراجعة عدد الصفوف عند التراجع.

هذا يصلح قراءة الوصف فقط؛ لا يعيد إنشاء صورة مصغّرة أو ملف مفقود، ولا يمنع
أداة استعادة خارجية من إدراج NULL لاحقًا.

## البناء والفحص

من مجلد Enterprise:

```bash
go build -o dist/workspace-file-metadata ./cmd/workspace-file-metadata
```

بعد وضع الأداة على البيئة المستهدفة، أمر الفحص فقط:

```bash
./dist/workspace-file-metadata \
  -config /opt/workspace-enterprise/config/config.json \
  -database sofa
```

الأداة تقرأ `SqlSettings` من **هذا الملف تحديدًا**؛ لا تدمج متغيرات البيئة
أو إعدادات systemd، ولا تشغّل التطبيق أو إضافاته. يجب أن يمثل الملف اتصال
الخدمة المقصود. لا تكتب بيانات الاتصال في تقريرها.

للتطبيق لاحقًا، بعد حفظ نسخة القاعدة ومراجعة تقرير الفحص، يضاف `-apply`
إلى الأمر نفسه ويحفظ تقرير JSON الناتج في مكان آمن. الأداة تحفظ وصف
الصفوف المتغيرة؛ لا تنشئ نسخة احتياطية كاملة من القاعدة.

**لم تُرفع الأداة إلى 209 ولم تُشغّل عليه أثناء هذه الجولة، وفق قيد المستخدم.**
