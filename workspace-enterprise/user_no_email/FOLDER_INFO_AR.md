# وظيفة مجلد `user_no_email`

مسارات إنشاء المستخدم أو إدارته عندما يكون البريد الإلكتروني اختياريًا في سياسة Workspace.
عند وجود الرخصة، يحد مسار إنشاء المستخدم جسم الطلب بـ1 MiB ويرفض قيمة
JSON إضافية بعد كائن المستخدم. يرد الجسم الكبير بـ`413` قبل إنشاء الحساب.
أثبت اختبار API أن الطلبات المرفوضة لا تنشئ مستخدمًا، مع بقاء إنشاء حساب
بلا بريد ودخوله يعملان. نجح `go test ./user_no_email -count=1` و
`go vet ./user_no_email` في 1 أكتوبر 2026.
مسار تفعيل وتعطيل المستخدم المرخّص يقبل كائن JSON واحدًا ضمن 4 KiB؛ يرفض
القيمة اللاحقة والجسم الكبير قبل تغيير حالة الحساب. أثبت اختبار API بقاء
المستخدم نشطًا عند الرفض، ثم نجاح تعطيله وإعادة تفعيله. نجح اختبار الجذر
الموجّه وحزمة `user_no_email` و`go vet` في 1 أكتوبر 2026.
مسار تعديل الأدوار يقبل حقل `roles` فقط ضمن 4 KiB ويرفض الحقول أو JSON
الإضافيين قبل تعديل الصلاحيات. أثبت اختبار API بقاء الدور الأصلي عند الرفض
ثم نجاح الترقية الصحيحة؛ نجح اختبار الجذر الموجّه وحزمة `user_no_email`
و`go vet` في 1 أكتوبر 2026.

تتيح مسارات الحالة المخصصة تعديلها وحذفها لحساب بلا بريد، ثم تعيد البريد
الفارغ بعد الحفظ؛ ويستعيد بدء الخدمة أي عنوان مؤقت بقي بعد توقف غير متوقع.
في 1 أكتوبر، صار الحفظ واستعادة العناوين المؤقتة عند بدء عقدة أخرى يتسلسلان
بقفل PostgreSQL مشترك؛ لا تمس الاستعادة عنوانًا تستعمله عملية حفظ جارية.
أثبت اختبارا التزامن انتظار الاستعادة حتى تحرير القفل، ونجاح طلبَي حالة
متزامنين مع بقاء البريد فارغًا بعدهما.
تعيين البريد المؤقت مشروط ببقاء البريد فارغًا؛ إذا تغير البريد في اللحظة
الفاصلة، يرد الطلب بتعارض بدل الكتابة فوق البريد الجديد. أثبت اختبار قاعدة
البيانات بقاء البريد الحقيقي.
يحد مسار تحديث الحالة المخصصة جسم الطلب بـ16 KiB ويرفض JSON اللاحق قبل
استعمال البريد المؤقت أو حفظ الحالة. أثبت اختبار API بقاء البريد فارغًا
والحالة غير مضبوطة بعد الرفض، ثم نجاح حفظ الحالة وحذفها. نجح اختبار الحزمة
و`go vet` في 1 أكتوبر 2026.
يُمنع العضو العادي من تغيير خاصية `show_last_active` عبر تحديث المستخدم
الكامل أو الجزئي؛ يستطيع المسؤول العام إدارتها. تعرض واجهة إعدادات العرض
هذا الخيار للمسؤول فقط. لا يتطلب هذان التعديلان خدمة خارجية، لكن تشغيلهما
على الموقع يتطلب بناء الخادم والواجهة ونشرهما.

ملفات بارزة: `service.go`، `service_test.go`.

هذا الوصف يحدد دور المجلد؛ حالة اكتمال الميزة وحدود اختبارها موثقة في [خطة النواقص](../docs/REMAINING_FEATURES_AR.md).

## توافق قواعد البيانات القديمة

تخزن هذه الميزة الحساب الذي لا يملك بريدًا بقيمة نصية فارغة `''`، لأن مسارات
قراءة المستخدم في Mattermost تفك حقل `users.email` إلى `string` ولا تقبل
`NULL`. عند نقل قاعدة قديمة تستعمل `NULL`، تظهر استجابة `500` في مسار
`GET /api/v4/users` حتى لو نجح إقلاع الخادم. يجب أخذ نسخة احتياطية قبل تحويل
قيم `NULL` الموجودة إلى `''`؛ الفهرس `idx_users_email_unique` يستثني البريد
الفارغ من شرط التفرد. لا تنشئ المسارات الحالية لهذه الميزة قيم `NULL` جديدة.

في 29 سبتمبر 2026، احتوت `sofa_backup` على 26 حسابًا ببريد `NULL` قبل
ترحيلات Mattermost. حُولت هذه القيم إلى `''` بعد نسخ القاعدة، ثم نجح جلب
صفحتي المستخدمين 0 و1 عبر `mmctl --local user list` دون تعديل كود السيرفر.
