# وظيفة مجلد `partial_search`

بحث جزئي إضافي عبر PostgreSQL مع واجهة API خارج مخزن الكور.
يحد معالج Enterprise جسم `POST /users/search` بـ1 MiB ويرفض قيمة JSON
ثانية بعد طلب البحث. ينطبق ذلك على HTTP و`mmctl --local` لأنهما يستعملان
المعالج نفسه، مع إبقاء حقول البحث والحد الأقصى للنتائج كما كانت.

ملفات بارزة: `api.go`، `service.go`، `service_test.go`.

هذا الوصف يحدد دور المجلد؛ حالة اكتمال الميزة وحدود اختبارها موثقة في [خطة النواقص](../docs/REMAINING_FEATURES_AR.md).

في 1 أكتوبر صُحح قيد رؤية المستخدمين في البحث المحدد بنطاق: تكفي مشاركة
فريق مسموح أو قناة مشتركة، وفق `UserCanSeeOtherUser`، بدل اشتراطهما معًا.
إذا لم توجد فرق أو قنوات مسموحة فلا يعيد البحث مستخدمين. أثبت اختبار API
أن مستخدمًا في فريق آخر لا يظهر قبل إنشاء محادثة مباشرة مشتركة، ثم يظهر
بعدها. نجح `go test ./partial_search -count=1` و`go vet ./partial_search`.
في 1 أكتوبر 2026، أثبت اختبار API بقاء البحث الصحيح ورفض JSON اللاحق
والجسم الكبير بـ`400` و`413`؛ نجح اختبار الحزمة و`go vet`.
يبقى قياس البحث على بيانات إنتاج كبيرة ونسخة قراءة متأخرة وعقدتين فعليتين.
