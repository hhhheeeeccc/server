# إعادة توجيه المرفقات داخل الخادم

ينسخ هذا المسار مرفقات رسالة يستطيع المستخدم قراءتها إلى قناة يستطيع
رفع الملفات وإرسال الرسائل إليها، دون تمرير محتوى المرفق عبر المتصفح.
يسجل `main.go` المسار مركزيًا عند إنشاء التطبيق. لا يعمل دون ترخيص،
ولا يستخدم إطار الإضافات.

```text
POST /api/v4/workspace/posts/{post_id}/files/forward
{"channel_id":"...", "file_ids":["..."]}
```

يرجع `201` مع `model.FileUploadResponse` وبيانات وصفية فقط. إنشاء الرسالة
المعاد توجيهها يأتي بعد ذلك عبر واجهة إنشاء الرسائل الأصلية.

## السلوك والقيود

- يفحص الجلسة وMFA والترخيص وتفعيل المرفقات وصلاحيات المصدر والوجهة،
  وسياسات تنزيل ورفع المرفقات. يرفض الرسائل المحذوفة والمحمية
  `burn_on_read` والقنوات المؤرشفة والمحادثات المباشرة المقيدة.
- يفحص موعد الرسالة المختفية من القاعدة الرئيسية قبل قراءة المرفق وقبل
  إرجاع النسخ الجديدة. يرجع `404` إذا انتهت، وينظف النسخ التي أنشأها
  الطلب إذا انتهت أثناء الرفع؛ فشل التحقق يرجع `503`. لا يعتمد هذا على
  سرعة عامل الحذف، ولا يمنع إعادة التوجيه قبل انتهاء الموعد ضمن الصلاحيات.
- يحتفظ بفلاتر إتاحة الرسالة وخطاف استهلاكها الأصلي، ويطبق خطاف السماح
  بتنزيل الملف ثم خط رفع الملفات الأصلي `UploadFileX` وحدود الحجم
  ومعالجة الصور وخطافات فحص الرفع. لم تختبر هذه الجولة إضافة فحص خارجية.
- ينشئ معرف ملف ومسار تخزين مستقلين لكل نسخة، وبملكية المستخدم الذي
  يعيد التوجيه. لا يشارك مسار التخزين مع الملف الأصلي.
- يعالج المرفقات بالتتابع، ويسمح بأربع عمليات نقل متزامنة لكل عملية
  خادم؛ عند الامتلاء يرجع `429`. هذا ليس حدًا مشتركًا بين عقد العنقود.
- عند فشل مرفق لاحق يحاول حذف النسخ التي اكتمل إنشاؤها في الطلب نفسه.
  فشل الرفع الأصلي جزئيًا قد يخلف كائنًا غير مكتمل بحسب سلوك التخزين
  الأصلي. نجاح النسخ ثم فشل إنشاء الرسالة قد يترك مرفقًا غير مرتبط.
- يراعي إلغاء سياق الطلب بين القراءات؛ لا يقدم مهلة قاطعة أو مقاطعة
  لعملية تخزين عالقة داخل `Read` أو `WriteFile`. معالجة الصور تستخدم
  سلوك الخادم الأصلي، ولا يُدعى انعدام التخزين المؤقت لجميع الأنواع.
- لا يوفر مفتاح idempotency: فقدان الرد ثم إعادة الطلب يمكن أن ينشئ نسخة
  إضافية. منع التكرار في النافذة يغطي الإرسال الجاري والنتائج التي وصل
  تأكيد نجاحها ضمن النافذة نفسها، ولا يغطي فقدان تأكيد الشبكة أو إعادة فتحها.
- لا يضيف سجل تدقيق مستقلًا لعملية النسخ عبر هذه الواجهة. يحتفظ بخطافات
  فحص الملفات الأصلية؛ هذا لا يساوي سجلات تدقيق تنزيل ورفع HTTP الأصلية.

## الواجهة

تستخدم `Client4.forwardPostFiles` معرفات الملفات فقط. تعود لطريقة التنزيل
ثم الرفع السابقة فقط عندما يرد الخادم بمعرف خطأ المسار غير الموجود
`api.context.404.app_error`، للتوافق مع الملفات التنفيذية القديمة. لا
تعود إليها عند رفض الصلاحيات أو فشل التخزين.

تعرض نافذة إعادة التوجيه حالة انتظار عربية، وتمنع الإرسال المتكرر وتغيير
الخيارات أثناء الطلب. أثناء نسخ المرفقات تتيح «إيقاف نقل المرفقات» دون
إغلاق النافذة؛ يقطع AbortSignal طلب النسخ أو معلومات الملف أو التنزيل
بما فيه قراءة الجسم أو الرفع. تحد مهلة خمس دقائق مجموع نقل مرفقات
الرسالة إلى وجهة واحدة، وتعرض رسالة عربية مع إتاحة المحاولة من جديد.
يفحص العميل الإلغاء قبل إنشاء الرسالة، حتى إن وصل رد نسخ ناجح متأخرًا.
بعد بدء إنشاء الرسالة الأصلية لا يعرض زر إيقاف النقل ولا يفترض التراجع
عن إرسال وصل إلى الخادم. تنفذ الرسائل والوجهات بالتتابع، وتتيح المحاولة بعد
خطأ مع تجاوز الرسائل التي وصل تأكيد نجاحها سابقًا. تُفتح القناة المباشرة
ويُستخدم معرفها الحقيقي قبل الإرسال والانتقال، ويجري الانضمام للقناة
العامة قبل رفع مرفقاتها.

الخادم الجاري.
