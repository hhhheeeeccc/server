# الترجمة التلقائية

تسجل `enterprise/main.go` خدمة `AutoTranslationInterface` مع مزود
LibreTranslate المحدد في إعدادات الخادم. تبقى الميزة مقفلة دون راية الرخصة
وإعداد التفعيل، وتستخدم مخزن الترجمة الأصلي وعضوية القناة واختيار لغة المستخدم.

يرسل طلب المزود نص الرسالة ومفتاح API إن ضُبط. تسمح الخدمة بتحويل HTTP داخل
أصل المزود نفسه فقط؛ ترفض التحويل إلى مخطط أو مضيف أو منفذ مختلف قبل إرسال
الطلب التالي، حتى لا يصل النص أو المفتاح إلى وجهة أخرى عبر `307` أو `308`.
إذا أعاد المزود خطأ HTTP مع جسم يكرر النص أو المفتاح، تعيد الخدمة رمز الحالة
فقط داخل خطأ `502` ولا تنقل جسم المزود إلى العميل.
إذا فشل إنشاء الطلب أو الاتصال بالمزود، لا تعيد الخدمة نص خطأ النقل الخام
الذي قد يتضمن عنوان المزود ومعاملات استعلام سرية. اختُبر إغلاق مزود محلي
مع قيمة سرية في عنوانه والتحقق من غيابها وغياب نص الرسالة من رد API.
عند قراءة ترجمة محفوظة، يُسمح بإنشاء ترجمة جديدة فقط إذا كان السجل غير
موجود فعلًا. خطأ التخزين أو فساد بيانات السجل يعيد خطأ خادم ويوقف الإرسال
إلى مزود الترجمة؛ اختبرنا سجلًا ذا `Meta` تالفًا، ثم استعادة السجل وإعادة
استعمال ترجمته، ثم إنشاء ترجمة لمعرّف جديد غير موجود.
في 1 أكتوبر صار فحص الترجمات المحفوظة يسبق طلب اكتشاف اللغة: إذا كانت جميع
لغات القناة المطلوبة جاهزة لنص لم يتغير، لا يُرسل النص إلى المزود مرة أخرى.
إذا نقصت ترجمة للغة أخرى، يبقى اكتشاف اللغة وترجمتها مطلوبين. أثبت اختبار
التكامل انعدام طلبات المزود عند خطأ التخزين أو اكتمال النسخ المحفوظة، وطلبًا
واحدًا للاكتشاف والترجمة عند غيابها. نجح `go test ./autotranslation -count=1`
و`go vet ./autotranslation` بعد التعديل.
يشمل الفحص أيضًا التحويل داخل الأصل ومنع وصول الطلب إلى خادم ثانٍ، ومنع تسرب
جسم خطأ المزود.
في 1 أكتوبر، صار قارئ الرد الناجح يرفض الجسم الذي يتجاوز 4 MiB وأي JSON
إضافي بعد القيمة الأولى. يعيد خطأ عامًا دون نسخ محتوى الرد إلى العميل؛
اختُبر الرد الصحيح الكبير ورد يحوي قيمتي JSON متتاليتين.
مهلة طلب المزود الافتراضية 5 ثوانٍ. تبقى القيمة المضبوطة كما هي إذا أمكن
تمثيلها في `time.Duration`، وتُحدّ عند أقصى مدة قابلة للتمثيل إذا تجاوزتها.
هذا يمنع تحول عدد مللي ثانية كبير جدًا إلى مهلة منتهية فورًا؛ اختُبرت
القيمة القصوى ونجح اختبار الحزمة و`go vet`.

من 18 أكتوبر، تستعمل المحاولة الأمامية في `Translate` أيضًا **مهلة واحدة
مشتركة** بقيمة `AutoTranslationSettings.TimeoutMs` لاكتشاف اللغة وجميع
لغات الوجهة غير المحفوظة. لا تتجدد هذه المهلة مع كل لغة؛ تبقى مهلة كل
طلب منفرد قائمة، وتسبقها مهلة المستدعي إن كانت أقصر. تبقى النتائج
المحفوظة صالحة الاستعمال دون إرسالها للمزوّد مجددًا.

إذا انتهت ميزانية المزوّد مع بقاء سياق المستدعي صالحًا، تتوقف طلبات
المزوّد الجديدة وتُحفظ اللغات غير المكتملة بحالة `unavailable`، تحت
حراسة مصدر المنشور المعتادة. تبقى لغة نجحت أو طابقت المصدر جاهزة أو
متجاوزة. تستعمل الكتابة سياق المستدعي، وتبقى حالة إلغائه وسحب الترخيص
مختلفة عن انتهاء ميزانية المزوّد؛ لا يُحفظ لهما رد متأخر. لا ينشأ
goroutine منفصل لإكمال طلب HTTP بعد رجوع الاستدعاء.

تلتقط مهمة الاستعادة الصفوف غير المكتملة بعد عمرها الأدنى المعتاد
(10 دقائق، مع دورة جدولة كل 5 دقائق)، دون الحاجة إلى ذاكرة الطلب
السابق. هذه ليست استعادة فورية أو ضمانًا لزمن وصول الترجمة. المهلة
الجديدة تحد انتظار مرحلة المزوّد في المحاولة الأمامية؛ **لا تحد زمن
API كله**، لأن قراءات SQL وحفظ كل لغة والتجهيز والبث تقع خارج هذا
الضمان. يحتفظ عامل الاستعادة بمهله السابقة لكل طلب ودورة.
[أدلة REST وWebSocket والاستعادة وحدود القياس](../../workspace-audits/workspace-enterprise-2026-10-22/audit/2026-10-18/autotranslation-provider-budget/README_AR.md).

إذا سُحبت رخصة Enterprise أثناء اكتشاف اللغة أو أثناء طلب ترجمة إلى لغة
معينة، يتوقف `Translate` قبل إرسال الطلب التالي وقبل حفظ نتيجة الطلب
المعلق. اختُبر السحب في الموضعين بخادم مزود محلي وقاعدة اختبار؛ السجلات
التي حُفظت قبل السحب تبقى كما هي. لا يمكن إلغاء طلب شبكة وصل إلى المزود
قبل لحظة سحب الرخصة، ولا يجعل ذلك حفظ لغات متعددة معاملة ذرية.
إذا أُلغي سياق الطلب أثناء الاتصال بالمزود، يوقف `Translate` بقية اللغات
ولا يحفظ حالة `unavailable` أو نتيجة متأخرة للغة التي أُلغي طلبها. تبقى
اللغات التي حُفظت قبل الإلغاء، بما فيها حالة تجاوز لغة المصدر. اختُبر
إلغاء طلب ترجمة محلي أثناء عمل المزود والتحقق من عدم حفظ نتيجة لغة المستخدم؛
نجح `go test -p 2 ./autotranslation -count=1 -timeout=2m` و
`go vet ./autotranslation` في 1 أكتوبر.
يغطي اختبار Enterprise
العام حفظ ترجمة منشور من مزود HTTP محلي.

## تحقق المزوّد الفعلي — 17 أكتوبر 2026

نجحت حزمة Go كاملة، **11 اختبارًا رئيسيًا دون تخطٍّ**، مع LibreTranslate
`1.9.6` ونموذجي Argos `en↔ar` بإصدار `1.0` وقاعدة PostgreSQL 16 مؤقتة.
شمل الفحص تسع حالات API وخدمة: صلاحيات القناة، ومفتاح المزوّد، واكتشاف اللغة،
وإنشاء المنشور وتعديله وترجمته في الاتجاهين، وتسليم لغة القارئ، وإعادة استخدام
المحفوظ دون طلب مزوّد جديد، وتفضيل المستخدم، وعطل شبكة محاكى، وسحب الرخصة.

كشف الفحص فقدان الجملة الثانية العربية عند استخدام MiniSBD الافتراضي:
أعاد المزوّد `Morning.` بدل كامل رسالة الاجتماع. أُعيد إنتاجه بطلب مباشر
مع الاكتشاف التلقائي وتحديد `ar` صراحة، ثم عولج في **وصفة تشغيل المزوّد**
باستخدام مجزّئ spaCy المدعوم من Argos. صورة CPU ووصف بناء مثبتان في
[دليل التشغيل](../deployment/autotranslation/README_AR.md). أثبتت إعادة
التشغيل بقاء معنى الاجتماع وموعده في ترجمة API، دون تغيير نص الرسالة أو
كود السيرفر. لا يستبدل هذا الفحص تقييم جودة الترجمة عمومًا.

[تقرير الأدلة والعينات](../../workspace-audits/workspace-enterprise-2026-10-22/audit/2026-10-17/autotranslation-libretranslate/README_AR.md)
يسجل بصمة الصورة والحزم والنماذج وأسماء الاختبارات الفعلية والمحاولات السابقة.
تتطلب النتيجة الجيدة وصفة المزوّد الجديدة؛ لم تُغيّر خدمة المستخدم الجارية.

كان انقطاع المزوّد في الدفعة السابقة يُحاكى بإرجاع وسيط الاختبار `503`،
وتستدعي إعادة المحاولة `Translate` صراحة. يوثّق القسم التالي التنفيذ الجديد؛
تبقى أدلة الدفعة السابقة كما هي ولا تثبت الاستعادة التلقائية وحدها.

## الاستعادة التلقائية

تجهز الدورة المفعّلة الآن الفهرس الجزئي
`idx_workspace_translation_recovery` على `(updateat,objectid,dstlang)`
لمنشورات LibreTranslate بحالتي `processing` و`unavailable`. يستبعد البحث
نتائج `ready` و`skipped` من مرشحي الاستعادة بدل مسحها مع كل عنصر.
يجري البناء بـ`CREATE INDEX CONCURRENTLY` داخل عامل الخلفية، دون تغيير
الصفوف أو إضافة مؤقت أو مسار API أو تأخير بدء الخدمة.

تدخل تهيئة الفهرس في مهلة دورة الاستعادة الحالية ذات الدقيقتين. تنسق
الاتصالات بقفل استشاري يُجرب ثم ينتهي استعلامه قبل الانتظار، حتى لا تعطل
لقطة انتظار قديمة بناء عقدة أخرى. يُبنى الفهرس الناقص، ويُعاد بناء الفهرس
غير الصالح إذا طابقت بنيته المتوقعة، ويُترك أي كائن بالاسم نفسه وبنية
مختلفة دون تعديل مع فشل الدورة. يعيد التشغيل الدوري المحاولة بعد الخطأ؛
لا يكفي `IF NOT EXISTS` لإصلاح بناء متوقف. لا يبدأ التركيب إذا كانت الميزة
غير مرخصة أو معطلة أو الخدمة مغلقة. تبقى صلاحيات DDL لازمة لحساب القاعدة،
وقد يؤجل البناء الطويل عمل الاستعادة إلى دورة لاحقة. لا يغير ذلك شروط
العمر أو التأخير أو الحجز أو الرخصة أو الحذف أو نشر نتيجة الاستعادة.
[الاختبارات والقياس وحدوده](../../workspace-audits/workspace-enterprise-2026-10-22/audit/2026-10-17/autotranslation-recovery-index/README_AR.md).

يشغّل العامل الأصلي `autotranslation_recovery` دورة كل خمس دقائق عندما تسمح
الرخصة والراية والإعداد. أصبحت صفوف `translations` بحالتي `unavailable`
و`processing` القديمة طابورًا دائمًا لإعادة الاستدلال؛ لا يوجد جدول أو ترحيل
إضافي. يحجز العامل صفًا بعملية ذرية مع `FOR UPDATE SKIP LOCKED`، ثم يحرر قفل
القاعدة قبل إرسال النص. يستخدم وقت PostgreSQL للحجز وتأخير المحاولة، حتى لا
تعتمد جدولة عقدتين على تطابق ساعتيهما.

- تبدأ أهلية الاستعادة بعد عشر دقائق من آخر تحديث؛ تُراعى أيضًا قيمة
  `meta.workspace_retry.next_at` بعد الفشل. الحجز الذي تجاوز عشر دقائق قابل
  للاستعادة بواسطة عامل آخر.
- يزداد التأخير عند الفشل: 10، 20، 40، 80، 160، 320 دقيقة، ثم ست ساعات كحد
  أقصى بين المحاولات. لا يوجد حد نهائي لعدد المحاولات، وتضاف مدة انتظار
  دورة العامل إلى هذه المواعيد.
- للدورة ميزانية دقيقتين وحد 1000 صف؛ لكل محاولة دقيقة واحدة أو ما بقي من
  مهلة الدورة، مع بقاء مهلة HTTP المضبوطة إن كانت أقصر.
- يختص العامل بمنشورات نصية عادية `type=''` من مزوّد `libretranslate`،
  في قناة غير محذوفة ومفعّل فيها خيار الترجمة، ولها قارئ نشط باللغة المطلوبة
  لم يعطّل الترجمة. لا يعالج منشورات النظام أو كائنات الترجمة المركبة.
- يقرأ النص الحالي من قاعدة الكتابة ولا يحتفظ بنسخة أخرى من نص المنشور.
  يعيد فحص الأهلية والرخصة قبل طلب المزوّد التالي وقبل الحفظ. فشل اكتشاف
  اللغة لا يولّد طلب ترجمة إضافيًا.
- يتطلب الحفظ بقاء الحجز والنص والأهلية؛ لا يكتب الرد المتأخر فوق حجز أحدث
  أو تعديل المنشور، وتُبطل قيمة ETag عند حفظ نتيجة جديدة.
- يلغي `Stop` و`Shutdown` طلبات العامل المعلقة. يُنشأ سياق جديد عند تشغيل
  العامل نفسه مجددًا؛ تفحص بوابة العامل الإعداد القديم والجديد كما يتطلب
  مدير المهام الأصلي.

طلب وصل إلى المزوّد لا يمكن سحب نصه منه عند تعطيل الميزة أو سحب الرخصة.
الحفظ مشروط بفحص الرخصة في التطبيق، وليس معاملة ذرية مع تغيير الرخصة في
الذاكرة. إعادة تسليم طلب إلى المزوّد ممكنة بعد انتهاء حجز أو انقطاع عامل؛
الحجز يمنع الرد القديم من استبدال نتيجة الحجز الأحدث.

نجحت اختبارات الاستعادة التسعة (25 حدث نجاح مع الفروع)، ثم الحزمة كاملة:
20 اختبارًا رئيسيًا و47 حدث نجاح مع LibreTranslate الحقيقي، دون تخطٍّ.
اختبارات الاستعادة التسعة جزء من العشرين وليست إضافة إليها.

[أدلة الاستعادة](../../workspace-audits/workspace-enterprise-2026-10-22/audit/2026-10-17/autotranslation-recovery/README_AR.md)
تسجل اختبارات الفشل والإصلاح والمزوّد الحقيقي وحدودها. فُحصت الواجهة
المكتبية في الدفعة التالية أدناه، ثم استُكملت دورة الحذف والاحتفاظ في
الدفعة الأخيرة الموثقة أدناه. يبقى الحمل وتعدد العقد المنشورة ونسخ القراءة
المتأخرة وسياسة احتفاظ المزوّد بالنصوص أعمالًا مستقلة.


## عرض الترجمة في المتصفح — 17 أكتوبر 2026

أعاد اختبار واجهة إنتاج المشكلة: يرجع API النص في `text`، بينما قرأت
الواجهة `object.message` فقط، فبقي الأصل ظاهرًا رغم جاهزية الترجمة.
عولج العرض في مساعد Webapp المشترك مع إضافة النوع الاختياري المطابق لـAPI،
وحُفظ دعم الترجمة المركبة والعودة للأصل عند تعطيل الميزة. رُبط عنوان نافذة
الأصل والترجمة بمعرّفه الفعلي لقارئ الشاشة. لم يُغيَّر السيرفر.

نجحت اختبارات مكوّن الرسالة الـ13 وTypeScript وESLint دون أخطاء، ثم الحزمة
كاملة مع علامة `integration`: 21 اختبارًا رئيسيًا و48 حدث نجاح دون تخطٍّ،
مع LibreTranslate الحقيقي وPostgreSQL وChromium 152. قدّم وسيط HTTPS بناء
Webapp إنتاجيًا مستقلًا، وأثبت عرض النص العربي ونافذة الأصل والترجمة،
وإلغاء التعطيل وتأكيده وبقاء التفضيل بعد إعادة التحميل ثم إعادة التفعيل.
لم تظهر استثناءات JavaScript غير معالجة، وبقي النص الأصلي في القاعدة كما هو.

المنشور في هذا الفحص أُنشئ عبر API؛ لا يثبت إرسال المحرر أو الوصول الحي
إلى جهاز ثانٍ أو واجهات الهاتف أو كل مسارات المواضيع والمرفقات واللغات.
[أدلة الواجهة والبناء وحدودها](../../workspace-audits/workspace-enterprise-2026-10-22/audit/2026-10-17/autotranslation-browser/README_AR.md).

## حذف الترجمات والاحتفاظ — 17 أكتوبر 2026

أثبتت الاختبارات بقاء الترجمات في ستة مسارات حذف. صار `main.go` يثبت
ربطًا في PostgreSQL يحذف مشتقات المنشور مع حذف مصدرها في المعاملة نفسها،
ويرفض إدراج رد متأخر بعد الحذف، وينظف الصفوف القديمة عند بدء التشغيل.
يعمل تنظيف الحذف مع غياب الرخصة أو تعطيل الترجمة؛ يبقى توليد النص مقفلًا
وفق الرخصة والإعداد.

نجحت الحزمة كاملة مع LibreTranslate وChromium: 29 اختبارًا رئيسيًا و68
حدث نجاح دون تخطٍّ، وأربعة اختبارات موجهة للاحتفاظ والتسجيل المركزي
وOpenID. تشمل اختبارات PostgreSQL ترتيبَي سباق الحذف والإدراج، وتراجع
الحذف، وتحديث عامل الاستعادة، والتثبيت المتزامن وفشل DDL ومهلة القفل.
يشمل عامل الاحتفاظ سياسة عامة والمثبتات وسياسات القناة والفريق.

[عقد التثبيت والحذف وحدوده](POST_LIFECYCLE_AR.md)، و
[أدلة التشغيل النهائية](../../workspace-audits/workspace-enterprise-2026-10-22/audit/2026-10-17/autotranslation-retention/README_AR.md).
استُكملت حماية سباق تحرير النص في الدفعة التالية أدناه. يبقى الإرسال من
المحرر والوصول الحي والهاتف واللغات الأخرى والحمل والعقد المنشورة ونسخ
القراءة المتأخرة وسياسة نصوص المزوّد. لا يثبت التنظيف حفظًا قانونيًا أو
إزالة النسخ الاحتياطية.

## تحرير النص أثناء طلب الترجمة — 17 أكتوبر 2026

أُعيد إنتاج أربع حالات: استبدال رد قديم للترجمة الأحدث، وبقاء النص المترجم
القديم بعد التحرير، وإرسال طلب ترجمة بعد تغير المصدر أثناء الكشف، وإرسال
نص متجاوز منذ البداية. يفحص `Translate` المصدر من الرئيسية قبل الإرسال
وقبل كل لغة وعند إعادة النتيجة. يحفظ ترجمة المنشور في معاملة قصيرة تقفل
