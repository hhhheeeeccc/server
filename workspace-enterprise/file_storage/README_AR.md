# التخزين وإحصاءات الملفات

تعرض `GET /api/v4/file_storage/usage` نوع المخزن وحجمه المستخدم. للمخزن المحلي
تُقرأ سعة نظام الملفات عبر `statfs`. في S3 وAzure لا توجد سعة كلية مماثلة،
لذلك يعرض المسار مجموع أحجام سجلات `FileInfo` غير المحذوفة فقط. يُحسب هذا
المجموع عند الطلب لأن عرض الكور المجمّع `file_stats` قد يبقى قديمًا بعد الرفع
حتى يحين تحديثه. لا يشمل المجموع كائنات أُضيفت خارج التطبيق أو بلا سجل.

تضيف الخدمة إلى `GET /api/v4/analytics/old?name=extra_counts` عدد الملفات
المرفقة وعدد الملفات غير المحذوفة التي سُجل لها تحميل. يُسجل التحميل عند
خدمة ملف مباشر برد `200` أو `206` لطلب `GET` فقط؛ لا تُحسب طلبات `HEAD`
أو ردود `304`، ولا تُرصد تنزيلات تتم من CDN أو برابط مباشر إلى المخزن.
يُحد تسجيل العدّاد في الخلفية إلى 32 عملية متزامنة لكل خادم. عند امتلاء
الحد يُسجل الطلب في goroutine المعالج نفسه بعد خدمة الملف، حتى لا تُنشأ
goroutines غير محدودة ولا يُسقط العدّاد بسبب ازدحام التسجيل. قد يزيد زمن
اكتمال الطلب عند امتلاء الحد أو بطء قاعدة البيانات، ويظل فشل الكتابة مسجلًا
في السجل دون إعادة محاولة دائمة.
تُحجب الإحصاءات المخصصة دون رخصة، وتُطبق صلاحيات التحليلات الأصلية.

## اختبار المخازن الثلاثة

ينجح `go test ./file_storage -count=1` على المخزن المحلي دون خدمات إضافية.
يتطلب اختبارا S3 وAzure محاكيَي MinIO وAzurite وشغّلهما قبل الاختبار.
يستخدم MinIO بيانات الدخول `workspace_test` و`workspace_test_secret`، ويستخدم
Azurite حسابه التطويري `devstoreaccount1`. يجب تشغيل Azurite مع
`--skipApiVersionCheck` لأن SDK الحالي يرسل نسخة API أحدث من المحاكي المحلي
3.34.0. أنشئ منفذًا محليًا لكل محاكٍ واضبط:

```sh
WORKSPACE_TEST_MINIO_ENDPOINT=127.0.0.1:<minio-port> \
WORKSPACE_TEST_AZURITE_ENDPOINT=http://127.0.0.1:<azurite-port>/devstoreaccount1/ \
go test ./file_storage ./data_retention_job -count=1
```

ينشئ الاختبار bucket وcontainer باسم فريدين، ثم يرفع ملفًا ويربطه بمنشور
ويقرأه ويفحص عداد التحميل والتحليلات ولوحة السعة. نجح الاختبار محليًا على
MinIO `RELEASE.2024-06-22T05-26-45Z` وAzurite `3.34.0`. تفحص حزمتا
`data_retention_job` حذف كائن منتهي وسجله وإبقاء كائن سارٍ في
المخزنين نفسيهما. هذه التجربة لا تثبت
صلاحيات حسابَي Amazon S3 وAzure الحقيقيين، أو سياسات الشبكة والتشفير لديهما.

اختبار التحميل المحلي يشغّل خادم الويب بوضع `gzip` ويتحقق من وصول العدادات
عبر API. أضيف اختبار لاستجابة التحليلات المضغوطة فعليًا من المعالج الأصلي:
يفك وسيط Enterprise ضغط `gzip`، يضيف العدّادين، ثم يعيد ضغط الجسم ويحذف
`Content-Length` و`ETag` القديمين. عند ترميز غير مدعوم أو بيانات مضغوطة
تالفة يمرر الاستجابة الأصلية دون تعديل؛ لا يدّعي ظهور العدّادين في تلك
الحالة.
في 1 أكتوبر، صار الوسيط يمرر الرد الأصلي تدريجيًا إذا تجاوز 4 MiB بدل
تخزينه كاملًا، ويحد فك ضغط `gzip` عند 8 MiB. تحقق اختبار الحزمة من بقاء
الحالة والترويسات والجسم عند تجاوز حد التخزين ورفض جسم مضغوط يتمدد فوق
حد الفك. في هاتين الحالتين لا تُضاف قيمتا الملفات إلى رد التحليلات.
