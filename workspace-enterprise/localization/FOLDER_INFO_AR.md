# وظيفة مجلد `localization`

كتالوج الترجمة العربية الخاص بالخادم ووسيلة تقديمه دون تعديل ملفات server.

ملفات بارزة: `service.go`، `translation_test.go`.

هذا الوصف يحدد دور المجلد؛ حالة اكتمال الميزة وحدود اختبارها موثقة في [خطة النواقص](../docs/REMAINING_FEATURES_AR.md).

في 1 أكتوبر، صار تعريب أخطاء API يحترم تفضيل `Accept-Language` بين العربية
والإنجليزية وقيمة `q`، ويرفض اختيار لغة بقيمة `q=0`. عند غياب تفضيل
لللغتين يستخدم `DefaultClientLocale`؛ لذلك تبقى العربية الافتراضية كما في
إعداد الخادم. نجح اختبار اللغتين وترتيبهما و`go vet` للحزمة. هذا يتعلق
بلغة رد الخادم؛ اختيار لغة واجهة المتصفح يعتمد أيضًا على تفضيل المستخدم
وإعدادات Webapp.

في واجهة إعدادات المستخدم، صار حفظ اللغة يرسل حقل `locale` وحده للحساب
الحالي، أو `id` و`locale` عند تعديل حساب من لوحة الإدارة. يتجنب ذلك إرسال
نسخة قديمة من بقية بيانات الملف الشخصي في طلب `patch`. أثبت اختبار Jest
شكل الطلبين، وأثبت اختبار المحدد أن لغة `en` المحفوظة تُستخدم بعد تحميل
الملف الشخصي مع بقاء الافتراضي `ar`؛ نجح TypeScript وESLint للواجهة المعدّلة.
اختبار API في `locale_api_test.go` غيّر لغة الحساب إلى `en` ثم `ar` عبر
`/users/me/patch`، وغيّرها المسؤول إلى `en` عبر مسار المستخدم، ثم قرأ
الحساب مجددًا وتحقق من حفظها مع بقاء الاسم والبريد. نجح `go test
./localization -count=1` و`go vet ./localization`. يبقى اختبار تغيير اللغة
من متصفح فعلي ثم تحديث الصفحة على الخادم المنشور.

في 1 أكتوبر، صار وسيط تعريب أخطاء API يحتفظ بحد أقصى 1 MiB من جسم رد
الخطأ. إذا تجاوز الرد الحد، يمرره أصليًا مع حالته بدل إبقائه كاملًا في
الذاكرة؛ لا تُترجم الرسائل في الرد الكبير. اختُبرت الكتابة المباشرة ومسار
`ReadFrom`، ونجح `go test -p 2 ./localization -count=1 -timeout=2m`
و`go vet ./localization`.

تقبل قائمة لغات Webapp الآن مسافات حول الرموز في `AvailableLocales`، مثل
`ar, en`، فتظهر العربية والإنجليزية كما في `ar,en`. نجحت اختبارات Jest
الثمانية وESLint وTypeScript. لا يضيف ذلك لغات أخرى إلى القائمة.
