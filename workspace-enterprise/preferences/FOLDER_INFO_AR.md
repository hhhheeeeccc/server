# وظيفة مجلد `preferences`

تحديث تفضيلات المستخدم مع التحقق من صلاحية الوصول للمنشورات المحفوظة.
يعالج مسار Enterprise القيمتين القديمتين `0` و`10000` لإعداد
`limit_visible_dms_gms` لأن فاحص النموذج الحالي يرفضهما؛ هذا المسار مشروط
برخصة، ويحفظ الدفعة في معاملة واحدة بعد فحص كل التفضيلات. بعد الحفظ يحدّث
القنوات الجانبية ويرسل حدثَي WebSocket وحدث
`PreferencesHaveChanged` للإضافات كما يفعل مسار التطبيق الأصلي.

اختبار API في `service_test.go` أثبت رفض الدفعة القديمة بلا رخصة، وعدم حفظ
بداية دفعة ذات قيمة غير صالحة، ثم حفظ قيمتي `0` و`10000` مع تفضيل آخر.
يحتاج إثبات استقبال الحدث داخل إضافة خارجية إلى إضافة تجريبية فعلية؛
الاختبار المحلي لا يشغّل إضافة. لا تحتاج عملية الحفظ خدمة خارجية.

حالة بقية الميزات موثقة في [خطة النواقص](../docs/REMAINING_FEATURES_AR.md).
