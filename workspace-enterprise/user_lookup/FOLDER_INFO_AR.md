# وظيفة مجلد `user_lookup`

جلب المستخدمين بمعرفاتهم مع قيود رؤية المستخدمين وصلاحيات الطلب. عندما
توجد رخصة، يعيد المسار `[]` لقائمة المعرّفات الفارغة. دون رخصة يمر الطلب
إلى مسار Mattermost الأصلي، الذي يرد `400` للقائمة الفارغة. يرفض مسار
Enterprise قيمة JSON `null` والبيانات اللاحقة بعد القائمة ووسيط `since`
غير الرقمي حتى مع القائمة الفارغة، ويزيل المعرّفات المكررة قبل القراءة.
يحد مسار Enterprise جسم الطلب بـ1 MiB ويرد `413` عند تجاوزه، بما في ذلك
البيانات اللاحقة بعد قائمة صحيحة. لا يضيف حدًا جديدًا لعدد المعرّفات داخل
الجسم المقبول.

اختبار API في `service_test.go` أثبت السلوك مع الرخصة وغيابها، والتحقق من
المدخلات، وإزالة التكرار، وأن مستخدمًا خارج الفرق والقنوات المرئية لا
يظهر بعد سحب صلاحية رؤية جميع الأعضاء. لا تحتاج التجربة خدمة خارجية؛ تبقى
تجربة نسخة قراءة متأخرة وعقدتين عند تغيّر العضويات والصلاحيات.
في 1 أكتوبر 2026، أثبت اختبار API رفض جسم أكبر من الحد بعد `[]` برد `413`؛
نجح `go test ./user_lookup -count=1` و`go vet ./user_lookup`.

حالة بقية الميزات موثقة في [خطة النواقص](../docs/REMAINING_FEATURES_AR.md).
