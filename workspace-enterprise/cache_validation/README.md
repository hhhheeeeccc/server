# نتيجة فحص التخزين المؤقت

تاريخ الفحص: 2026-10-15. الاختبارات تستخدم كود Workspace الفعلي دون تعديل
تنفيذ الكاش في `mattermost/server` ودون الاتصال بقاعدة بيانات المستخدم أو
خادم Redis موجود مسبقًا.

## ما نجح

- اختبارات حزمة `platform/services/cache` الموجودة: LRU والتخزين المتوازي
  وانتهاء الصلاحية والتسلسل والإزالة.
- تحقق إعدادات النموذج وتغطية Redis بإعدادات صحيحة وخاطئة.
- Redis حقيقي بإصدار 7.4.0، بكلمة مرور اختبارية، داخل حاوية مؤقتة على
  `127.0.0.1` ومنفذ عشوائي. الحاوية تُحذف بعد الاختبار.
- التخزين والقراءة لأنواع `model.User` والبيانات العامة والأعداد.
- القراءة المتعددة، والمفاتيح غير الموجودة، والإزالة المتعددة وPurge مع
  الحفاظ على مساحة أسماء كاش أخرى.
- انتهاء الصلاحية، وانتشار التحديث والحذف بين اتصالين مستقلين.
- الزيادة والنقصان الذريّان مع ثمانية عمال متزامنين.
- عزل قواعد Redis رقم 0 و1، وعزل بادئات المفاتيح.
- تشغيل الحالات مع كاش عميل Redis مفعّلًا ومعطّلًا.
- رفض كلمة مرور Redis الخاطئة، وإخفاء كلمة المرور في إعدادات لوحة التحكم.
- تشغيل الاختبارات المضافة باستخدام `go test -race` دون بلاغات تسابق.
- اختبارات الواجهة ونموذج الإعدادات: 38 اختبارًا ناجحًا، تشمل حقول Redis
  وصلاحيات التعديل والترخيص وتحويل القيم إلى بيانات الحفظ.

## ملاحظات التشغيل

1. الصورة التي أرسلها المستخدم تعرض `RedisDB = -1`. هذه القيمة مرفوضة
   عندما يكون `CacheType = redis`؛ يبدأ ترقيم قواعد Redis من `0`.
2. عنوان `localhost:6379` الظاهر كنص توضيحي ليس قيمة اتصال محفوظة. يلزم
   إدخال عنوان فعلي قابل للوصول من خادم Workspace.
3. ملف `mattermost/server/config/config.json` المحلي كان يستخدم `lru`
   بعنوان Redis فارغ. نجاح الاختبارات لا يعني أن Redis مفعّل في النشر الفعلي.
4. تفعيل Redis في مسار تشغيل الخادم يتطلب ترخيصًا يتيح `Cluster`، كما هو
   منصوص عليه في `channels/app/platform/service.go`. لم تُنشأ تراخيص ولم
   يُتجاوز هذا الشرط؛ الاختبارات تختبر مزود الكاش مباشرة.
5. إبطال كاش عميل Redis غير متزامن. فحص القراءة مباشرة بعد الحذف التقط
   قيمة قديمة في تشغيل أول؛ اختبار وصول الإبطال ضمن مهلة قصيرة نجح. في
   إعادة القياس ظهر الحذف بعد نحو 0.25 مللي ثانية مع كاش العميل مفعّلًا؛
   هذا قياس محلي واحد وليس ضمان زمن. اختبار الاتصالين ينتظر وصول الإبطال
   ثم يفحص القيمة. `DisableClientCache=true` يعطّل هذا الكاش المحلي في
   عميل Redis داخل خادم Go، وليس كاش متصفح المستخدم.
6. هذه الصفحة تتطلب إعادة تشغيل الخادم لتطبيق تغيير نوع الكاش وإعدادات
   الاتصال. لم تُغيّر إعدادات المستخدم ولم يُعد تشغيل خادمه أثناء الاختبار.
7. إعداد `RedisPassword` الحالي في مخطط الواجهة من نوع `text`: القيمة
   المحفوظة تُخفى من الخادم، لكن كلمة مرور جديدة تُكتب في حقل نص عادي.
   لم يُغيّر تنفيذ الواجهة ضمن طلب الاختبار هذا.

## إعادة الاختبار

من مجلد `mattermost/server`، مع Docker محلي وصورة `redis:7.4.0` متاحة:

```bash
go test ./platform/services/cache -count=1
python3 ../../workspace-enterprise/cache_validation/run.py
```

سجل Redis التفصيلي: `/tmp/workspace-cache-validation.log`.

من `mattermost/webapp/channels`:

```bash
../node_modules/.bin/jest --config jest.config.js --runInBand \
  src/components/admin_console/admin_definition_cache_settings.test.tsx \
  src/components/admin_console/schema_admin_settings.test.tsx
```

لا يغطي هذا الفحص النشر الفعلي أو حفظ الإعدادات عبر HTTP أو إعادة التشغيل
عليه، ولا يقدم اختبار تحمل أو ضمانًا لعدد مستخدمين متزامنين.
