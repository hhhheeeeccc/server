# محرر الرسائل المرئي

## الإعداد

الملف `server/config/workspace-visual-editor.json` في المشروع، أو
`config/workspace-visual-editor.json` بالنسبة إلى مجلد تشغيل السيرفر:

```json
{
    "Enabled": true
}
```

يمكن للمدير تغيير التفعيل من **لوحة التحكم ← تجريبي ← حالة الميزات ← محرر
رسائل مرئي**. يحفظ المفتاح التغيير فورًا في هذا الملف ويبلغ المستخدمين عبر
WebSocket، دون إعادة تشغيل السيرفر. يحتاج التعديل صلاحية كتابة حالة الميزات؛
صلاحية القراءة وحدها لا تسمح بالحفظ.

تُقرأ الإعدادات من الملف عند بدء التشغيل. إذا عدّلته يدويًا، أعد تشغيل السيرفر؛
لا توجد مراقبة دورية للملف.
لا تحتاج متغيرات بيئة أو Python أو Go overlay. ملف الإعداد مستقل عن
`server/config/config.json` ولا تمسحه عمليات حفظ إعدادات السيرفر.

التسجيل المركزي في `server/workspace-enterprise/main.go` يستخدم المسار
`config/workspace-visual-editor.json` بالنسبة إلى مجلد تشغيل السيرفر.
يبدأ Docker من `/opt/workspace` ويضم الملف الافتراضي ضمن الحزمة؛ لا يعتمد
التنفيذ على مجلد مصدر خارج المستودع أو مسار مطلق لجهاز المطور.

## التفعيل في الحساب

يمكن البناء والتشغيل من مجلد `server/workspace-enterprise` باستخدام
`make run-server`. راجع [دليل البناء والنشر](../../../BUILD_GITLAB_AR.md).

بعد بناء نسخة Enterprise والواجهة المحدثة وتشغيل السيرفر، حدّث صفحة الموقع،
ثم افتح **إعدادات الحساب ← خيارات متقدمة ← تحرير النص المنسق**، واختر
**المحرر المرئي** واحفظ. المحرر المرئي هو الافتراضي في الواجهة للحسابات التي
لم تحفظ تفضيلًا سابقًا، بما فيها الحسابات الجديدة. يظل اختيار المحرر العادي
المحفوظ سابقًا محترمًا، ويمكن تغييره من إعدادات الحساب.
تبقى هذه الإضافة مقفلة دون ترخيص Enterprise محمّل. عند إضافة ترخيص بعد بدء
الجلسة، حدّث الصفحة لقراءة حالة التفعيل الجديدة.

## الربط

- حزمة Go مستقلة، مسجلة من نقطة Enterprise المركزية القائمة.
- Middleware على `GET /api/v4/config/client` فقط، بما في ذلك المسار الفرعي
  المعرّف في `SiteURL`. يحافظ على معالج السيرفر الأصلي والاستجابة الأصلية.
- تضيف الاستجابة المفتاح `WorkspaceVisualEditorEnabled` دون تغيير أعلام
  الميزة الأصلية أو مخزن إعداداتها.
- تدعم الاستجابات غير المضغوطة و`gzip` و`zstd`؛ يُحافظ على نوع الضغط بعد
  إضافة المفتاح. يشمل الاختبار طلب Chrome الذي يفضّل `zstd`.
- مسار `GET/PUT /api/v4/workspace/visual_editor/settings` محمي بجلسة المستخدم
  وصلاحيات لوحة التحكم والترخيص. لا تتغير الحالة إذا فشل حفظ الملف.
- محدد الحالة في الواجهة يقرأ هذا المفتاح لتفعيل الخيار الموجود أصلًا.
  يبقى المفتاح محفوظًا في Redux عند وصول `config_changed` من السيرفر.
- إزالة الترخيص تقفل التفعيل في الواجهة. تسجيل الخروج يمسح إعداد الجلسة.
- إذا كان الملف غائبًا، يبدأ الإعداد معطلًا وتبقى واجهة إعداده متاحة للمسؤول.
  أما الملف غير الصالح أو خطأ قراءته فيُسجَّل، ولا يضاف تجاوز Enterprise.

لا توجد تعديلات على ملفات مصدر `mattermost/server` لهذه الميزة.

## التحقق المحلي

من مجلد Enterprise:

```bash
go test -mod=readonly -race ./visual_editor
```

من `mattermost/webapp/channels`:

```bash
../node_modules/.bin/jest --runInBand --runTestsByPath \
  src/packages/workspace-redux/src/selectors/entities/visual_editor.test.ts \
  src/packages/workspace-redux/src/selectors/entities/general.test.ts \
  src/packages/workspace-redux/src/reducers/entities/general.test.ts
```

اختبارات Go تغطي قراءة الإعدادات ورفض الملفات غير الصحيحة، والترخيص،
والمسار الفرعي، وسلامة تمرير الأخطاء والطرق الأخرى. اختبارات الواجهة تغطي
تفعيل المحرر بتفضيل المستخدم، وبقاء الإعداد بعد تحديث إعدادات السيرفر،
وتسجيل الخروج، والتوافق مع النسخ التي لا توفر إعداد Enterprise الجديد.
تشمل اختبارات مفتاح لوحة التحكم التحميل والحفظ والفشل وصلاحية القراءة
والعرض بالعربية. تشمل اختبارات الحفظ الخلفية الكتابة المتزامنة، واستعادة
الإعداد عند التشغيل، وعدم إرسال تحديث إذا فشلت الكتابة.
