# إشعارات ID-only

تسجل `enterprise/main.go` خدمة `NotificationInterface`. عند طلب تأكيد إشعار
`ID-only` عبر `/api/v4/notifications/ack`، يتحقق مسار API الأصلي من جلسة
المستخدم وإذنه لقراءة المنشور قبل استدعاء الخدمة. تعيد الخدمة معرّف الرسالة
والقناة والفريق والمرسل ونصًا عامًا مترجمًا؛ لا تعيد محتوى الرسالة داخل
الإشعار. يتطلب هذا المسار رخصة Enterprise.
يتحقق التنفيذ من راية الرخصة `IDLoadedPushNotifications` تحديدًا؛ وجود رخصة
بلا هذه الراية لا يفعّل إشعارات ID-only. اختُبر السماح بالراية والرفض عند
إطفائها أو غياب الرخصة.

نجح اختبار API محلي مع وكيل Push اختباري: أعاد الطلب المصرح به معرّف
المنشور والمرسل الصحيحين، ورُفض منشور قناة خاصة لم ينضم إليها المستخدم
بحالة `403`. يغطي اختبار الخدمة أيضًا رفض الاستدعاء دون رخصة. نجح
`go test ./notification -count=1` و`go vet ./notification`.

الوكيل في الاختبار يستقبل تأكيد الإشعار فقط؛ لا يثبت إرسال Push إلى هاتف،
أو مصادقة وكيل مخصص وتجديد رمزها، أو عرض الإشعار في تطبيق الهاتف. هذه
المتطلبات تحتاج وكيلًا وتطبيقًا حقيقيين، وعقد المصادقة في
`../push_proxy/CONTRACT_AR.md` ما زال مفتوحًا.
