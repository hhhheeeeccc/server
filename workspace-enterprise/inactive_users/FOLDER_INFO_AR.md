# وظيفة مجلد `inactive_users`

تعطيل الحسابات غير النشطة عبر
`POST /api/v4/users/deactivate/inactive` وفق مدة الأيام التي يحددها مسؤول
يملك صلاحية إدارة المستخدمين، مع رخصة Enterprise. يستثني حسابات مسؤولي
النظام والبوتات، ويلغي جلسات الحسابات التي عُطلت ويحدث حالة حضورها.
يقبل الطلب كائن JSON واحدًا يحوي `days` فقط، بحد 4 KiB. يرفض الحقول أو
قيم JSON الإضافية، ويرد `413` عند تجاوز حد الحجم قبل تعطيل أي حساب.

يمنع حساب الحد الزمني تجاوز `int64` عند إدخال عدد أيام ضخم: إذا تجاوزت
المدة عمر الطابع الزمني الحالي منذ بداية Unix، لا يطابق أي نشاط صالح ويرد
العدد صفرًا. أثبت اختبار API أن أكبر قيمة `int` لا تعطل مستخدمًا قديم
النشاط. نجح `go test ./inactive_users -count=1` و`go vet ./inactive_users`،
ونجح اختبار الجذر `TestDeactivateInactiveUsersRevokesExistingSessions` الذي
يغطي التعطيل الفعلي وإبطال الجلسة لمدة عادية.
في 1 أكتوبر 2026، أثبت اختبار API أن الحقل غير المعروف وJSON اللاحق والجسم
الكبير تُرفض مع بقاء المستخدم نشطًا. نجح اختبار الحزمة و`go vet`.

يُحفظ سجل `WorkspaceInactiveUserSessionCleanup` وتنتهي صلاحية الجلسات الموجودة
في عبارة SQL نفسها التي تعطل الحسابات. تُلغى الجلسات التي أُنشئت حتى وقت
التعطيل فقط عبر مسار التطبيق الأصلي فورًا بعده، وتُحذف النية بعد النجاح.
هذا الحد الزمني يطبق على المحاولة الفورية وإعادة المحاولة، حتى لا تُلغى
جلسة جديدة بعد إعادة تفعيل الحساب. عند فشل الحذف تبقى النية في
القاعدة المشتركة، ويعيد عامل الخلفية المحاولة كل دقيقة
بحد أقصى 50 حسابًا وبقفل `SKIP LOCKED` لتوزيع العمل بين العقد. لا تلغي
إعادة المحاولة جلسات أُنشئت بعد وقت التعطيل. إذا انقطع طلب المسؤول بعد
تثبيت التعطيل، تستمر المحاولة الفورية بسياق مستقل، ثم يتولى العامل الباقي.
يجرد مسار الإلغاء الجلسات من قاعدة الكتابة مباشرة؛ لأن قراءة نسخة متأخرة
قد تعيد قائمة فارغة وتمحو نية التنظيف بينما تبقى جلسات على القاعدة الأصلية.
يحمل الجرد معرّف الجلسة ورمزها ونوع OAuth وبيانات الجهاز والخصائص اللازمة
لمسار الإلغاء الأصلي. اختُبر جرد الجلسات الموجودة واستبعاد جلسة أُنشئت بعد
حد التعطيل، ثم نجاح إعادة المحاولة. لم تُحاكَ نسخة قراءة متأخرة فعلية.
فشل إنشاء جدول التنظيف أو إنهاء صلاحية الجلسات يمنع تثبيت التعطيل بدل ترك
جلسات دون تتبع. تُمسح كاشات الجلسات بعد التثبيت على العقد. أثبت اختبار
فشل الحذف أن طلب API بجلسة قديمة يرد `401` مع بقاء سجل الإعادة. لا يغطي
الاختبار قبول طلب بدأ قبل التعطيل أو انقسام العقد الفعلي.
أثبت اختبار فشل تحديث `ExpiresAt` تراجع التعطيل كله وبقاء الحساب نشطًا.

نجح اختبار API لإلغاء الجلسة وإزالة النية، واختبار استئناف نية محفوظة من
قاعدة البيانات، ومحاكاة فشل حذف جلسة ثم رفض الجلسة المنتهية ونجاح إعادة
المحاولة، وفحص
`go vet ./inactive_users`. ما زال اختبار تعطل مخزن الجلسات الفعلي وسقوط
العقدة في وقت الإلغاء والتشغيل متعدد العقد، وقياس زمن عبارة التعطيل عند
عدد كبير من الجلسات، مطلوبًا.
