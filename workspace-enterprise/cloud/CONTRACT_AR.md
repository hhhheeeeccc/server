# عقد تكامل Cloud

## نقطة الربط

`server/einterfaces/cloud.go` و`RegisterCloudInterface` في `main.go`. سُجلت
واجهة آمنة تعيد `ErrUnavailable` من جميع عمليات Cloud بدل قيمة نجاح أو
بيانات ثابتة؛ تمنع انهيار مسار إشعار تغيير فلتر IP الذي يستدعي
`GetCloudCustomer` بعد الحفظ. لا توجد خدمة CWS موصولة. تُنفذ واجهة الاشتراكات والمنتجات
والعميل والفواتير والتثبيت وتغيير الترخيص عبر خدمة Cloud موثوقة، لا ببيانات ثابتة.

## شروط التنفيذ

- هوية تثبيت وحساب Cloud موثقتان، واعتماد خدمة محمي ومجدَّد؛ تفويض كل طلب
  بحسب المستخدم والتثبيت. لا تحفظ رموز الخدمة في السجلات أو ردود API.
- مصدر واحد موثوق لحالة الاشتراك والحدود. تتطابق `GetCloudLimits` وبيانات
  الرخصة بعد تغيّر الاشتراك، مع إبطال الذاكرة المؤقتة بين العقد.
- عمليات تغيير الاشتراك والفوترة قابلة لإعادة المحاولة دون تكرار الأثر، ولها
  سجل تدقيق واضح. فشل CWS يعاد خطأً، ولا ينتج اشتراكًا أو رخصة افتراضية.
- ملفات الفواتير والشهادات تُقرأ وتُحفظ مع تحقق الحجم والنوع والصلاحية؛ لا
  تُفترض إمكانية الوصول إلى CWS من مجرد وجود الواجهة.

## قبول الميزة

اختبارات خدمة CWS تجريبية حقيقية لتبديل الخطة، التحديث، انقطاع الخدمة، تدوير
الاعتماد، صلاحيات المستخدم، وعقدتين تتلقيان تغيير الترخيص نفسه. لم تُنفذ بعد.
