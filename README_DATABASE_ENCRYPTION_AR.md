# إعداد اتصال قاعدة البيانات بنموذج الليسنس

السيرفر يحتوي **المفتاح العام فقط**، ومشروع الإصدار المنفصل على سطح المكتب
يحتوي **المفتاح الخاص**. تعطي مشروع الإصدار رابط PostgreSQL، فيصدر قيمة
موقّعة. تضعها في `SqlSettings.DataSource`، ويتحقق السيرفر منها تلقائيًا عند
تحميل الإعدادات، ثم يستخدم رابط الاتصال في الذاكرة.

**هذا توقيع رقمي مع ترميز، وليس تشفيرًا سريًا لكلمة المرور.** يمكن استخراج
الرابط من القيمة الموقّعة دون أي مفتاح. المفتاح الخاص يتيح إصدار قيم يقبلها
السيرفر، والعام يتحقق من صحتها. هذا هو نموذج الليسنس الذي طلبته. إذا كان
المطلوب إخفاء كلمة المرور عمّن يقرأ الملف، فلا يحقق هذا النموذج ذلك؛ التشفير
السري يتطلب سرًا لدى السيرفر لفك التشفير.

## مكان كل ملف

| الملف | مكانه ووظيفته |
| --- | --- |
| المفتاح العام | `server/config/database-public.pem` داخل هذا المشروع؛ مضمّن في البرنامج أثناء البناء. |
| المفتاح الخاص | `/home/marwan/سطح المكتب/fg/database/generate_database_config/database-private.pem`؛ للإصدار فقط، خارج مشروع السيرفر. |
| أداة الإصدار | `/home/marwan/سطح المكتب/fg/database/generate_database_config/generate_database_config.py` |
| الإعدادات | `server/config/config.json`؛ تحفظ القيمة التي تبدأ بـ `signed:rsa:v1:`. |
| كود القراءة والتحقق | [config/signed_sql.go](config/signed_sql.go)، وربطه بتحميل وحفظ الإعدادات في [config/store.go](config/store.go). |

المفاتيح مستقلة عن مفاتيح الليسنس الموجودة في `fg/license/generate_license`.
لم نغيّر مفاتيح الليسنس أو طريقة عملها. لا تنسخ المفتاح الخاص إلى مشروع السيرفر
ولا إلى Git. صلاحيات مجلد الإصدار `700` والخاص `600`.

## كيف يعرف السيرفر المفتاح؟

تعليمة `go:embed database-public.pem` تضمّن العام داخل الملف التنفيذي أثناء
بناء السيرفر. لذلك لا يحتاج السيرفر إلى مسار للخاص، ولا Python، ولا تشغيل
مشروع الإصدار، ولا متغير بيئة يحدد المفتاح.

عند تحميل الإعدادات:

1. يتعرف على البداية `signed:rsa:v1:` ويفك ترميز الوثيقة.
2. يتحقق بالمفتاح العام من توقيع `RSA-PSS-SHA256` على الرابط مع بادئة الإصدار.
3. يرفض القيم غير الصحيحة أو الموقّعة بمفتاح آخر قبل محاولة اتصال SQL.
4. يمرّر الرابط الأصلي إلى PostgreSQL في الذاكرة.
5. يحتفظ بالقيمة الموقّعة عند حفظ إعدادات أخرى، ولا يكتب الرابط الواضح بدلًا منها.

يشمل ذلك `DataSource` و`DataSourceReplicas` و`DataSourceSearchReplicas`.
تغيير اتصال موقّع من خلال حفظ إعدادات السيرفر يتطلب قيمة موقّعة جديدة؛ السيرفر
لا يملك الخاص ليصدرها. تبقى الإعدادات القديمة ذات الروابط العادية مدعومة.

## تغيير قاعدة البيانات بالتفصيل

### 1. جهّز القاعدة الجديدة

أنشئ قاعدة ومستخدمًا بصلاحيات مناسبة، وتأكد من عنوان المضيف والمنفذ وكلمة
المرور وإعداد TLS. إصدار النص الموقّع لا ينشئ القاعدة ولا يعدّل مستخدم PostgreSQL.

بنية الرابط، بأسماء توضيحية فقط:

```text
postgres://USERNAME:PASSWORD@HOST:5432/DATABASE?sslmode=require&connect_timeout=10
```

استخدم إعداد TLS المناسب لبيئتك؛ `verify-full` يتحقق أيضًا من اسم المضيف
والشهادة عند إعداد شهادات موثوقة. `sslmode=disable` يعطّل TLS. توقيع الرابط
لا يشفّر حركة الشبكة.

رمّز الرموز الخاصة داخل اسم المستخدم أو كلمة المرور بترميز URL، مثل
`demo@123` تصبح `demo%40123` في جزء كلمة المرور. لا ترمّز الرابط كاملًا.
عند إدخال الرابط إلى الأداة، استخدم `&` بين خيارات الاتصال. إذا احتوى الرابط
المنسوخ من JSON على النص الحرفي `\u0026`، تصحح أداة الإصدار هذا الفاصل داخل
الخيارات تلقائيًا قبل التوقيع. لا تغيّر بيانات الدخول قبل علامة `?`.

### 2. أصدر قيمة بالخاص نفسه

```bash
cd "/home/marwan/سطح المكتب/fg/database/generate_database_config"
python3 generate_database_config.py
```

يفتح الأمر واجهة محلية في المتصفح. ألصق الرابط الكامل في حقل «رابط قاعدة
البيانات»، واضغط «إنشاء الرابط»، ثم «نسخ الناتج». الإدخال مخفي افتراضيًا،
ويمكن إظهاره بالزر المجاور. أبقِ الطرفية مفتوحة أثناء الاستخدام وأغلقها
باستخدام Ctrl+C عند الانتهاء. إذا لم يفتح المتصفح، افتح العنوان الذي يظهر
في الطرفية. استخدم الخاص الموجود؛ لا تولّد زوجًا جديدًا عند تغيير القاعدة.

يمكن حفظ الناتج في ملف محمي بدل عرضه:

```bash
umask 077
python3 generate_database_config.py --cli > connection.signed
```

الناتج حساس لأنه قابل للقراءة بعد فك الترميز. لا ترسله ولا ترفعه إلى Git.
تعتمد الأداة على Python وحزمة `cryptography` المذكورة في `requirements.txt`؛
الحزمة متوفرة على الجهاز الحالي. هذه الاعتمادات مطلوبة في جهاز الإصدار فقط.

### 3. خذ نسخة احتياطية وأوقف السيرفر

أوقف السيرفر بالطريقة التي تشغله بها، مثل Ctrl+C في طرفيته أو إيقاف خدمته.
احفظ نسخة محمية من ملف الإعدادات الحالي خارج المستودع قبل التعديل. مثال:

```bash
cd "/home/marwan/المستندات/mattermost/server"
install -d -m 700 /home/marwan/.local/state/workspace-config-backups
umask 077
cp config/config.json "/home/marwan/.local/state/workspace-config-backups/config-$(date +%Y%m%d-%H%M%S).json"
```

### 4. استبدل قيمة الاتصال فقط

افتح `server/config/config.json`، ثم استبدل `SqlSettings.DataSource`:

```json
"SqlSettings": {
    "DriverName": "postgres",
    "DataSource": "signed:rsa:v1:COMPLETE_GENERATED_TOKEN"
}
```

هذا مقتطف توضيحي: احتفظ بباقي إعدادات `SqlSettings` الموجودة، وضع الناتج
الفعلي مكان `signed:rsa:v1:COMPLETE_GENERATED_TOKEN`. احفظ JSON صالحًا.
إذا كانت لديك نسخ قراءة أو بحث، أصدر قيمة مستقلة لكل رابط واستبدل عناصر
`DataSourceReplicas` و`DataSourceSearchReplicas` أيضًا.

متغيرات `MM_SQLSETTINGS_*`، إن كانت مضبوطة في الخدمة أو الطرفية، تتقدم على
قيم الملف كالمعتاد. راجعها إذا اتصل السيرفر بقاعدة مختلفة عن التي كتبتها.

### 5. افحص الاتصال ثم شغّل بالطريقة المعتادة

```bash
cd "/home/marwan/المستندات/mattermost/server"
./bin/mattermost db ping -c ./config/config.json --timeout 10s
./bin/mattermost -c ./config/config.json
```

يمكنك أيضًا استخدام الأمر المعتاد:

```bash
make run-server
```

التحقق ضمن تحميل إعدادات السيرفر، وليس داخل سكربت تشغيل خاص. استخدم باينري
مبنيًا من الكود المعدّل، أو ابنِه من جديد إذا نسخت المشروع لجهاز آخر:

```bash
go build -trimpath -tags 'enterprise sourceavailable production' \
  -ldflags '-X github.com/mattermost/mattermost/server/public/model.BuildEnterpriseReady=true -X github.com/mattermost/mattermost/server/public/model.BuildHashEnterprise=workspace-enterprise' \
  -o bin/mattermost ./cmd/mattermost
```

استخدم وسوم البناء المناسبة لنسخة مشروعك عند اختلافها. لا تشغّل مثيلين
على المنفذ نفسه.

## تغيير الرابط لا ينقل بياناتك

قاعدة مختلفة تعني بيانات مختلفة. إذا أردت نقل المستخدمين والرسائل، خذ نسخة
احتياطية متسقة من القاعدة القديمة واستعدها في الجديدة باستخدام أدوات
PostgreSQL مثل `pg_dump` و`pg_restore`، وانقل ملفات Mattermost إذا لزم.
نفّذ النقل مع إيقاف الكتابة أو وفق خطة ترحيل مناسبة، ثم غيّر الرابط.

## حفظ المفتاح وتغييره

احفظ نسخة آمنة من مجلد الإصدار خارج Git. فقدان الخاص لا يمنع تشغيل القيم
الصادرة سابقًا، لكنه يمنع إصدار روابط جديدة بهذا الزوج.

إذا قررت تغيير زوج المفاتيح، تحتاج إلى الخاص الجديد في مشروع الإصدار، والعام
المقابل في `server/config/database-public.pem`، ثم إعادة بناء ونشر السيرفر
وإصدار كل قيم الاتصال بالمفتاح الجديد. استبدال ملف العام بعد البناء وحده
لا يغيّر المفتاح المضمّن داخل الباينري.

القيم القديمة التي تبدأ بـ `encrypted:rsa:v1:` تخص آلية التشفير السابقة،
ولا يقرأها هذا التنفيذ. احتفظ بمفتاحها ونسخها الاحتياطية إن احتجت لاستعادتها؛
حوّل الرابط إلى قيمة موقّعة باستخدام أداة الإصدار قبل تشغيل التنفيذ الحالي.

## أخطاء شائعة

- `invalid signed SQL connection`: القيمة ناقصة أو عُدّلت أو صدرت بمفتاح
  مختلف. أصدرها مجددًا بالخاص المطابق للعام المضمّن.
- `changed SQL connections require a new signed value`: حاولت حفظ رابط
  عادي جديد بدل اتصال موقّع. أصدر القيمة من مشروع سطح المكتب.
- `password authentication failed (28P01)`: وصل الاتصال إلى PostgreSQL، لكنه
  رفض بيانات الدخول. راجع الرابط وصلاحيات المستخدم وكلمة مروره، ثم أصدر
  قيمة جديدة. التوقيع لا يصحح بيانات الدخول.
- `connection refused` أو انتهاء المهلة: راجع تشغيل PostgreSQL والعنوان
  والمنفذ وإعداد الشبكة.
- `wrong value for "sslmode"` ومعه `disable\\u0026...`: صدر الناتج سابقًا
  برابط يحتوي فواصل JSON كنص حرفي. افتح أداة الإصدار المحدّثة وأعد إصدار
  الرابط، ثم استبدل القيمة وأعد التشغيل؛ لا تعدّل حروف القيمة الموقّعة نفسها.

المفتاح العام داخل المشروع لا يمنع شخصًا يملك صلاحية تعديل إعدادات السيرفر
أو باينريه من تغييرهما. استخدم صلاحيات ملفات ونظام مناسبة، وتعامل مع ملف
الإعدادات والنصوص الموقّعة بوصفها بيانات اعتماد.
